## Full-module machine-code audit anomaly

The actual disassembly showed:

```
_dev_info
-> _dev_emerg
-> panic
```

with the helper call absent, as intended for the CP03 stop.

However, the Python string-position audit reported:

```
ORDER_DEV_INFO=502
ORDER_DEV_EMERG=807
ORDER_PANIC=56
HELPER_CALL_POS=-1
STOP: CP03 cold-path call order invalid
```

This is currently classified as a **tooling/audit failure, not a scientific or build failure**.

Reason: the audit used:

```python
panic = s.find('panic')
```

over the entire disassembly text. The text contains the pathname:

```
.../r297-checkpoint-panic/cp03-fullmodule/...
```

before the disassembled call site, so the first occurrence of the substring `panic` is very likely the pathname rather than the relocation/call target.

Therefore:

- full module build: PASS
- required/forbidden marker contracts: PASS
- lifecycle symbol contract: PASS
- direct inspection of CP03 cold path: consistent with intended order
- automated machine-code order checker: FAIL due to likely substring-matching bug
- LIVE CP03: NOT RUN
